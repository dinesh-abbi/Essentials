# Release Changelog v1.0.21

*Released on: Monday, 18 August 2026*

**OTA update reader, scroll-reveal tab bar, and widget midnight reset.**
A focused polish pass that replaces the cramped update modal with a full-screen changelog reader, brings the tab bar to life with blur and scroll-reveal, and fixes the widget silently showing yesterday's water total past midnight.

### 🚀 New Features

- **Full-screen update reader (`src/app/update.tsx`)**: Replaces the old 340 dp modal — changelog is now a proper scrollable screen that shows an installed → new version chip, progress bar during download, and a sticky "Install Update / Later" action bar. Reaches the same screen from Profile's "What's New" row and the launch-time check.
- **"What's New" reader (`src/app/whats-new.tsx`)**: New route accessible from Profile → App Version. Shows release notes for the currently installed version by default; falls back to latest when the exact version has no GitHub release. Displays an inline banner and hands off to `/update` when GitHub has something newer — no duplicate download logic.
- **OTA update utilities (`src/utils/updates.ts`)**: All GitHub Releases plumbing extracted into one shared module (`fetchLatestRelease`, `fetchReleaseForVersion`, `checkForUpdate`, `downloadAndInstall`, `markUpdateSeen`, `hasSeenUpdate`). Numeric semver comparison so 1.0.10 correctly beats 1.0.9. Update is offered once per release (persisted via `AsyncStorage`) so the check never nags on every launch.
- **Changelog parser (`src/utils/changelogParser.ts`)**: Hand-rolled markdown parser that turns release bodies into typed sections (features / fixes / ui / build / commits / other). Section classification uses word-boundary regex, not substring match — avoids "build" being silently filed under "ui". Inline tokenizer handles `**bold**` and `` `code` `` runs so the UI can style them instead of showing raw markers. Unrecognised or auto-generated bodies degrade gracefully to an "other" section rather than rendering blank.
- **`ChangelogView` component (`src/components/ChangelogView.tsx`)**: Shared presentational reader used by both `/update` and `/whats-new` so the two screens can never drift apart. Responsive two-column grid above 700 dp. Each section card shows an icon, count pill, and colour-coded accent rail per item.
- **Scroll-reveal tab bar (`src/utils/tabBarVisibility.ts`)**: Tab bar now slides down out of view while scrolling down content and springs back up on a scroll-up or when reaching the top. Driven by a Reanimated mutable (`tabBarHidden`) so the value is updated on the UI thread every frame — no React re-render per scroll event. Reveal is suppressed entirely under `useReducedMotion()`.
- **Blur target registry (`src/utils/blurTarget.ts`)**: Tiny module-level registry that bridges each screen's `BlurTargetView` ref to the tab bar's `BlurView`. Screens call `registerBlurTarget(ref)` on focus; the bar reads `useActiveBlurTarget()` — solves the Android "blur whatever is behind me" limitation without threading a prop through the navigator.

### 🐛 Bug Fixes

- **Widget midnight reset (`widget-native/WaterWidgetProvider.kt`)**: Widget no longer shows yesterday's water total on days when the app was never opened. `updateWidget()` now compares a stored `KEY_SYNC_DATE_KEY` (local-timezone YYYYMMDD int) against today; on mismatch it zeroes `water_ml` and `logs_today` before painting. Runs on every OS-triggered 30-minute `onUpdate` tick, so the reset happens automatically at local midnight even with no user interaction.
- **`OTAUpdateChecker` no longer draws UI**: The component was rebuilt as a pure side-effect (no JSX returned). It now navigates to `/update` instead of drawing its own modal, waits for Firebase auth to resolve and requires a signed-in user so it can't race the auth guard's `/login` redirect, and skips the `login`, `alarm`, and `update` route groups. Navigation is guarded by a `useRef` so a single check can never trigger two navigations.
- **Tab bar blur tint fixed in dark mode**: `expo-blur`'s `BlurView` defaults to `tint='default'` which resolves to a white overlay — in dark mode this washed the whole bar out to light grey. Explicit `tint={isDark ? 'dark' : 'light'}` plus a translucent brand-colour tint layer on top now look correct in both modes.
- **Tab bar scroll-reveal never strands the bar off-screen**: Each tab screen calls `showTabBar()` in its focus effect, so landing on a tab after scrolling another tab down can't leave the bar stuck below the viewport.

### 🎨 UI Improvements

- **Tab bar — real backdrop blur**: Replaced the solid translucent surface (`rgba(…, 0.96)`) with a `BlurView` using `blurMethod="dimezisBlurViewSdk31Plus"` and a `blurTarget` wired to the focused screen's `BlurTargetView`. A separate tint `View` on top (`rgba(20,26,35,0.52)` dark / `rgba(255,255,255,0.58)` light) ensures the bar looks intentional even on Android < 12 where the blur can't kick in.
- **Tab bar — labels added**: Each tab button now shows a 9.5 pt label below its icon (icon shrunk from 22 → 19 pt to compensate). Active label weight is 700, inactive is 500. Accessibility role, state, and label are wired to the `Pressable`.
- **Tab bar — pill animation respects `Reduce Motion`**: `handlePressIn`/`handlePressOut` scale springs are skipped entirely when the system accessibility flag is set.
- **Home screen — hero card skeleton reordered**: Skeleton loading state now shows the water hero card first (full-height, matching the real card's capsule ring + timeline + quick-log buttons), then the secondary stat row below — matching the actual card hierarchy instead of showing the secondary widgets first.
- **Home screen — secondary stat cards trimmed**: Spend widget drop-shadowed sub-label row removed from skeleton; Attendance skeleton avatar shrunk from 56 px to 44 px. Cards now match the proportions of the real content more closely.
- **Home screen — water hero reordered to top**: Real dashboard layout now mirrors the skeleton: hydration hero card first, then the spend/attendance widget row. Visual hierarchy comment added to mark the intent explicitly.
- **Profile screen — App Version row now tappable**: Navigates to `/whats-new`. Shows a `v{version} ready` signal pill when an update is available on GitHub, or a subdued "What's new" hint when up to date.
- **Profile screen — `Row` component extended**: Accepts optional `onPress`, `accessory`, `iconColor`, and `iconBackground` props. When `onPress` is provided the row renders as a `TouchableOpacity` with a chevron. Backwards-compatible — all existing rows without `onPress` are unchanged.
- **Profile + Home — scroll-reveal and blur wired up**: Both screens wrap their root in `BlurTargetView`, register with `blurTarget.ts` on focus, and attach `useTabBarScrollHandler()` to their `Animated.ScrollView`. Both also call `showTabBar()` on focus.
- **`TabBar` token in `theme.ts`**: New exported `TabBar = { height: 64, floatOffset: 12 }` constant; `app-tabs.tsx` and `BottomTabInset` both derive from it. The old separately-hand-kept `TAB_BAR_BOTTOM_INSET` export was removed (replaced by `BottomTabInset` from `theme.ts`).
